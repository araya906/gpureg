# Roadmap (nightly runs take the first unchecked item)

- [x] Make the first validation run pass end to end (harness and package were written without being executed).
- [x] Add a float32 accuracy report to the validation (max errors vs float64) without failing the gate.
- [x] Lasso float32: the fixed `1e-12 * |f|` acceptance slack in `_backtrack` is below float32 rounding, so L keeps doubling and the path stalls (coef error 0.6 vs float64 in the report). Make the slack dtype-aware (e.g. a few `finfo(dtype).eps`); a quick trial gave ~1e-6.
- [x] float32 screens: default `tol=1e-9` is below float32 resolution, so `converged` can be False on good fits (binomial 98%); scale the default tol by dtype.
- [x] float32 p-values: return p in float64 (float32 p underflows below ~1e-38; 1-2 of 100 features in the float32 report).
- [x] Lasso float32 tol: a float32 fit with tol=1e-10 runs to max_iter and warns, although coefficients match float64 to ~3e-7; floor tol at the dtype's rounding error as in `_newton`.
- [x] Add a scikit-survival `CoxnetSurvivalAnalysis` reference for Cox lasso (optional dependency; skip if unavailable).
- [x] Add a separation / constant-feature scenario and check that `singular` and `converged` flags are set sensibly.
- [x] Flag infinite estimates explicitly (quasi-separation in GLM, monotone likelihood in Cox): today they report `converged=True` with huge SE and p near 1, as R does but without R's warning.
- [x] GLM: support offsets (e.g. log person-time for poisson).
- [x] Cox: support strata (`cox_screen`/`cox_fit`).
- [x] Cox: support start-stop (left-truncated) data.
- [x] Lasso: strong-rule screening to skip inactive features along the path.
- [x] Optional sandwich (robust) standard errors for GLM (`robust=True`, HC0).
- [x] Optional sandwich (robust) standard errors for Cox (Lin–Wei, as `coxph(robust=TRUE)`; check vs statsmodels PHReg / lifelines if available).
- [x] Benchmark the automatic chunk-size heuristic on larger simulated data (CPU) and document results.
- [x] CPU chunk size: the 2 GB CPU budget gives chunks 1.3-2.2x slower than 16-64 models (validation/results/bench_chunks.md); lower the CPU default (e.g. a budget or cap giving ~16-64 models) and re-run the benchmark.
- [x] Cox chunk memory: `copies = 8 + 2 * max_ties` overestimates peak memory 10-160x with heavy ties (chunk 1 at n >= 20000); size the tie term from the actual padded Efron tensors and check measured peak vs estimate in the benchmark.
- [x] Cox lasso: support `strata=` in `lasso_cv(family="cox")` (Breslow partial likelihood with risk sets within strata, reusing `_risksets`; CV deviance per stratum-aware risk set); check vs scikit-survival or a stratified reference if available, else vs unpenalized `cox_fit(strata=)` at lambda -> 0.
- [ ] Cox lasso: support `entry=` (start-stop / left truncation) in `lasso_cv(family="cox")`, combining with strata; check vs unpenalized `cox_fit(entry=)` at lambda -> 0 and an episode-splitting test.
